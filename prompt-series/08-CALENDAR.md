# 08 — FAMILY CALENDAR: native Apolosign first

Use Apolosign's standard native Calendar Mode as source of calendar interaction for this initial release. Configure each parent's chosen shared iCloud calendar(s) using manufacturer-supported connection and permissions; use a dedicated shared family calendar for household events to avoid displaying private work/medical details. The iPhone Calendar app displays multiple accounts, so distinguish iCloud vs Outlook-backed events and test the actual account. Apolosign advertises two-way iCloud/Google sync; do not assume Outlook write-back or corporate account access. Verify current documentation: https://www.apolosign.com/collections/digital-calendar and https://support.apolosign.com/hc/en-us/articles/54233946858009-What-Are-Calendar-Mode-and-Android-Mode-on-the-Apolosign-Digital-Calendar

Provide an animated calendar door/tile with clear launch/switch instructions from HOMEBASE. Research documented Android launcher/deep-link capability on exact firmware; if unsupported, use one clear manual switch, a native Android companion only if justified, and documented return path. Do not fabricate intents, automate private APIs, scrape the native UI or claim web app can directly start proprietary app. Test actual device; provide fallback when running browser-only demo. Include adult event visibility controls.

Optional later: add read-only calendar glance to HOMEBASE using independently authorized provider adapter (iCloud CalDAV with supported credentials, Microsoft Graph for allowed Outlook accounts, Google Calendar OAuth). Use least privilege, secure server-side encrypted tokens, incremental sync or documented polling, recurrence and timezone correctness, all-day events, deletions, stable IDs and source label. Apple third-party access: https://support.apple.com/en-us/121539. Avoid duplicate events from multiple providers and loops; never silently replicate calendars. If enabling writes later, explicitly choose source calendar and prove create/edit/delete bidirectionality with two phones and native device, handle conflicts via provider ETags/version and clear status. Do not assume app-specific passwords or authorization work on every account; no credential in client logs. No production calendar data on public preview. Only parent-approved coarse labels (e.g. daycare or family outing) visible in child view; avoid exposing locations, attendees, medical or employer details.

Deliver connection checklist for both parents, test matrix with create/edit/delete on each device, native-vs-custom limitations, failure recovery and logout/revocation. Native calendar remains usable even if HOMEBASE offline or unavailable.
