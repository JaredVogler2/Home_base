# 11 — PARENT STUDIO and useful longitudinal history

Create a mobile-first adult management console with household settings, child profile editor, visual task/routine designer, reward catalog and approval inbox, academy link management, integrations status, shopping lists, device pairing and logs, exports, deletion and AI controls. Wall parent mode should be locked and easy to exit. Adult views can use text/tables; child views remain picture-led.

Implement history with explicit purpose and retention: (a) task occurrence/completion/approval/skip and effort configuration; (b) routine step completion and assisted vs independent, coarse duration; (c) XP ledger and redemption fulfillment/refunds; (d) Academy session aggregate and skill domain only with consent; (e) shopping purchase/check history and recurring items; (f) integration health, sync errors and device changes; (g) optionally parent-authored milestones/notes. Avoid collecting raw touch streams, continuous microphone/camera, locations, detailed medical/behavioral labels, or child chat logs. Calendar and photo metadata minimal, no copies without reason. Defaults configurable: recent operational data 90 days, aggregated trends 12 months or chosen retention; financial-style XP ledger retained for reconciliation until profile deletion, with documented export/deletion policy. No permanent surveillance. Parent can export JSON/CSV, delete child profile and associated data, pause history, correct records and remove integrations.

Create weekly family recap and simple charts: routine completion trends by time-of-day, activities requiring help, XP inflow/outflow, reward goal progress, time since purchase, category practice balance. Provide denominators and missing-data flags; distinguish observations from inference and avoid child rankings or developmental diagnoses. Keep comparisons within individual over time only where appropriate. Include optional household milestone timeline parents curate. Test data minimization, deletion cascades, export fidelity, ledger reconciliation, timezone and permission checks. Design history APIs with bounded summaries, not unrestricted LLM access.
