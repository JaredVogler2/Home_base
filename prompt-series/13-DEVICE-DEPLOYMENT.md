# 13 — Vercel deployment, Android wall operation and reliability

Build private production deployment with one HOMEBASE project initially and the existing independent Academy deployment. Document Vercel project settings, build commands, runtime version, database provisioning options, env var inventory (names only), migration strategy, preview/demo isolation, rollback and CI. Use Git integration for automatic deployments after review; no real secrets or private data in logs or public repo. Vercel preview URLs must not inadvertently expose live data; enforce app-level auth rather than assuming obscure URL is private. Set CSP, strict allowed origins, secure cookies, CSRF protection, rate limits and request validation. Separate read/write provider credentials and revoke workflows. No service worker caching auth responses or secrets. Secure media access and lifecycle. Use Vercel-supported scheduled job intervals and managed services when necessary; document cost and alternatives. Maintain minimal health endpoint with no PII and safe telemetry.

Device manual: verify exact Apolosign 27-inch 4K model, Android version, Chrome/WebView version, memory, actual resolution/CSS DPR, touch/audio, Wi-Fi, native calendar and photos, default launcher, kiosk app availability and permissions. Use browser first, then install PWA or Fully Kiosk Browser if needed (https://www.fully-kiosk.com/); distinguish free vs license features and Android permission limitations. Add startup URL, landscape orientation, screen timeout, sleep schedule, wake behavior, quiet hours, crash recovery and guided return path. Evaluate whether native calendar/photos and kiosk can coexist; do not lock user out of settings. Android wrapper/launcher or native bridge only if capability proven and approved; explicit no-kiosk fallback. Do not silently replace native home or force device admin permissions.

PWA: installable manifest/icons, offline app shell, cached safe assets, IndexedDB outbox, background sync where supported plus foreground reconnect fallback; robust service worker versioning so queued data survives updates. Pause heavy motion when hidden, avoid 4K animation overdraw, image decode budget, performance profiling, thermal/long-running tests. Restore safe navigation state after reboot, reconnect and idle. iPhone app-like layout and installation guide for both parents. Test Chrome/WebKit, different viewport/DPR, no WebGL fallback, reduced motion, interrupted internet and 24-hour soak (or explicitly mark not run). Add docs/DEVICE-CHECKLIST.md and docs/DEPLOYMENT.md. No unsupported automatic return/launch claims.
