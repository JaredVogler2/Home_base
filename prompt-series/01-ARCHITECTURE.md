# 01 — Architecture and project strategy

Design a modular monolith first: Home_base repository, one HOMEBASE Vercel deployment with wall (/wall), mobile parent (/parent), pairing, authenticated APIs and an optional child route. Keep the already existing Training_Academy repository/Vercel deployment independent; document integration contract and release coordination. Split further only for clear reasons (e.g. distinct security boundary or independent release cadence), not aesthetic microservices. A monorepo with multiple deployable apps is acceptable if justified. Use the current supported stack (e.g. Next.js/TypeScript, CSS motion/SVG/Rive/Lottie or carefully chosen Three.js, managed Postgres with realtime via Supabase or equivalent). Evaluate licensing and bundle cost. Avoid duplicating Training Academy's engine.

Propose boundaries: identity/device pairing; household/roles/profiles; task templates/occurrences; routines; rewards/ledger; academy adapter; calendar bridge; shopping; media; reporting; AI; sync engine; shared visual primitives. Separate presentation and domain rules. Use versioned schemas and migrations, typed provider interfaces, transactional writes and explicit error states. The database is authoritative for shared state, not localStorage. For offline, use IndexedDB for approved cached data and an outbox with client-generated operation IDs. Reconcile with server revisions, backoff and deduplication. Never rely on a Vercel function's local filesystem, in-memory timer or permanent connection. Prefer managed realtime or polling; scheduled work must use verified platform capabilities/limits or database scheduling.

Produce ADRs, an entity diagram, route map, integration capability matrix, threat model, cost estimates for a household at low/moderate usage and an implementation backlog. Plan demo/local/preview/prod environments with separate DBs and secrets. Production app private even though repositories are public. Use least-privilege adult credentials and device-scoped sessions; no service-role credentials in browser. Keep modules operational without integrations.
