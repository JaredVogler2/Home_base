# 03 — Identity, household model and sync

Create adult accounts for two or more guardians, invite flow, household membership, device registration via expiring one-use code or QR, revocation, and child profiles accessible by avatar. Adult settings and approvals require authenticated mobile session or rate-limited PIN unlock on trusted wall display, with inactivity relock; enforce permissions server-side (a child-facing route is not security). Separate permissions for child mode, wall device, guardian and optional guest. Prevent arbitrary child profile changes from enabling privileged operations. Provide recovery/reset without losing household records.

Define typed data model: households, memberships, profiles (nickname/avatar/age band only), devices, preferences, task templates, occurrences, task completions, routine versions/steps/runs, reward catalog, ledger transactions, redemption requests, academy link/progress summaries, shopping lists/items, provider connections, optional media, activity events and audit records. Use household scoping and RLS or equivalent for every query. Unique operation keys, optimistic version checks, foreign keys, integer units for XP, timestamp+household timezone for local occurrences, soft delete or tombstones where sync requires it. Handle DST and recurrence changes without duplicate XP or retroactively rewriting history.

Implement event outbox and idempotent server endpoints. For concurrent edits on two phones, document conflict behavior by entity (e.g. list item field version, ledger never last-write-wins). Surface syncing/pending/offline on wall and parent screens, not fake success. Cache only minimum allowed information; encrypted storage when feasible and purge on device revoke/signout. Test cross-household isolation, replay, expired pair code, concurrent reward redemption, profile switching, offline queue recovery, backup/restore, migrations and accessibility. Produce API/schema documentation and synthetic fixtures.
