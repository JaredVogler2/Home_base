# 12 — Optional AI: useful, bounded and privacy-aware

Design an adult-facing Family Copilot that is disabled by default and optional. Use provider abstraction for OpenAI or Anthropic API (owner supplies separate API credentials; do not assume chat subscription includes API). Verify current models and SDK docs; use server-side Vercel AI SDK/provider integration or equivalent, model IDs configurable, structured outputs validated with schema, typed read-only tools, bounded context, low-cost default, per-request token cap, timeout, retry, daily/monthly spend cap and kill switch. Never expose secrets or use child-facing unrestricted chat. Parent chooses which data categories leave system; default send only anonymized/aggregate data, no names, photos, voice, calendar details or sensitive notes. Disclose provider, retention/data terms, cost and categories; avoid keeping raw prompts/responses unless opted in. No claim of guaranteed zero retention unless contract supports it.

Build high-value workflows with evidence and review:
- Routine Architect: turn "school tomorrow, need shoes and backpack" into illustrated routine draft with sequence/dependencies/estimated durations; parent approves.
- Schedule-aware mission planner: from authorized coarse calendar and household constraints propose quieter/busier day plan, defer optional chores and suggest preparation; no auto calendar write.
- Reward economist: deterministic ledger simulation plus AI explanation of how long until goals at realistic earning rates; suggest price adjustments to adults, never manipulate child or change balances.
- Weekly reflection: summarize trends with denominators, uncertainty, no diagnoses; cite internal event IDs or date ranges and propose 1–2 experiments (e.g. split cleanup into smaller tasks).
- Learning bridge: suggest offline games for domains practiced in Academy, short parent-guided activities and picture-led mission cards; no claims of assessment or mental health evaluation.
- Shopping intelligence: categorize, normalize quantities, detect potential duplicates, propose reusable staples/checklist from history or event plan; never purchase.
- Family briefing: synthesize approved events, routines and pending rewards into concise parent digest.
- Story/illustration scripts: generate adult-reviewed original visual routine scripts and simple read-aloud adventures; no unreviewed generated media or private photo uploads.

Use a proposal envelope (type, evidence refs, rationale, uncertainty, changes, safety flags, cost estimate). Parent previews/edits/accepts; deterministic server validators enforce permissions, dates and all reward rules. LLM cannot mutate ledger, approve rewards, delete data, buy items or contact third parties. If applying draft, show diff and confirmation, use typed domain actions with audit/idempotency. Treat provider calendar text, links and list content as untrusted input; isolate from instructions, no arbitrary URL fetch, no external tool invocation, no secrets in prompt. Test prompt injection, invalid JSON, budget cap, disabled key, provider outage, unsupported inference, partial data and refusal of child-facing freeform interaction. All core features remain functional without AI.
